# Artifact Manifest

One repository, three provenance layers. Every directory below is included as-is; nothing has been re-run for the
camera-ready except the CPU test log and the generated tables/figures. Raw per-example output files of four run
families (listed in `RAW_OUTPUTS_IN_RELEASE.txt` next to each run) live in the GitHub release tarball, not in git;
every summary file the paper uses is in git.

## Layer 1 — main experiments (May 2026; unchanged since the review-time supplement)

- `code/`: the `safekv` package, `code/scripts/`, `code/tests/` (29 test modules), `code/requirements.txt`,
  `code/pyproject.toml`, and the `code/configs/` mirror. This is the July 2026 state of the tree (it adds the
  actual-forwarding runner path and the July 2026 scripts); the review-time snapshot is preserved by the
  SHA-256 values listed in `paper_reference/claim_audit/`.
- `configs/`: YAML configs for every packaged run. The `risk:` block is not consumed by the selector (README).
- `data/`: processed JSONL datasets (diagnostics, noise sweeps, position sweeps, HotpotQA-500, 2Wiki-500, selector splits).
- `results/`: per-example outputs (`answer_eval_outputs.jsonl`), summaries (`answer_eval_summary.json`), metric CSVs
  (`answer_eval_metrics.csv`), failure reports, early prototype latency runs, bootstrap and held-out calibration
  outputs, selector artifacts, and consolidated table inputs under `results/paper_tables/`.
- `paper_reference/`: `final_tables/` and `final_figures/` mirrors, `claim_audit/` reports from the review-time build,
  plus `camera_ready_tables/` (generated for this version) and, in `final_figures/`, every camera-ready figure PDF
  (all regenerated by `scripts/camera_ready/make_figures.py`, which writes the CSVs and calls `draw_figures.py`) with the plotted values of each data figure as a `.data.csv`;
  the review-time versions of the redrawn schematic and robustness figure are kept as `submitted_figure1_setup.pdf`
  and `submitted_figure5_external_sanity.pdf`.
- `scripts/`: `verify_packaged_results.py`, `emit_reproduction_commands.py`, `rebuild_headline_tables.py`,
  `reproduce_paper_results.sh`, `fetch_raw_outputs.sh` (release tarball), and `camera_ready/` (table/figure
  generators and the tie-break audit).

## Layer 2 — actual-forwarding, staleness and latency runs (July 2026; `results_rebuttal/`)

Directory-level status (`results_rebuttal/README.md`) and claim-level status (paper Appendix T) are authoritative.
Cited directories:

- `actual_recompute_{hotpot,2wiki}_500/` — actual suffix forwarding on the original inputs (Table 2a).
- `actual_vs_copy_{hotpot,2wiki}_500_l40s_v2/` — same-run donor-copy vs actual-forwarding reconciliation (App. H).
- `neutral_selector_actual_{hotpot,2wiki}_shuffle{101,202,303}_100/` and `neutral_selector_actual_3seed_validation/` — score-neutral shuffled runs (Table 2b, App. H).
- `staleness_doccount_full_50_v3/` — 5x5x7 staleness grid, 26,250 rows, validator PASS (Table 6, App. U).
- `latency_{hotpot_original,2wiki_original,2wiki_neutral_shuffle101,n16_neutral_layout101,noise64}_50_v1/` — L40S latency traces with validators and paired bootstraps (Table 7, App. K).
- `quality_noise64_actual_riskk1_50_v1/` — Noise64 answer-quality gate on the timed examples (App. K).
- `oracle_kv_drift_2wiki_neutral_shuffle101_100_v3/` — full-reference token-local diagnostic (App. M; nondeployable).
- `cpu_selector_audit_l40s_host/` — selector-only CPU cost and label-free selector quality (App. K/N).
- `all_document_ceiling_*_v1/` — execution-partition positive controls (not cited in the paper; retained).
- `data/` — score-neutral, shuffled, and nested input variants with `.summary.json` sidecars.
- `frontier_*`, the remaining `smoke_*`, `resume_audit_*` — superseded or smoke runs per the ledger; never cited.
  The six directories the ledger marks `DEBUG_ONLY` or `INVALID_DO_NOT_CITE` are not in the repository.

## Additions on `main` after tag `v1.0.0`

- `minimal/`: SAFE-KV in one file (`safekv_minimal.py`), its README and CPU tests; separate from the code that produced
  the paper's runs, which is unchanged.
- `scripts/camera_ready/draw_figures.py`: draws the camera-ready figures from the plotted-value CSVs;
  `make_figures.py` now writes the CSVs (byte-identical) and calls it. The figure PDFs in
  `paper_reference/final_figures/` and four generated-table captions in `paper_reference/camera_ready_tables/` are
  the camera-ready versions; no value changed.
- `paper/SAFE-KV_AACL2026_Findings.pdf` (camera-ready paper), `assets/` (README images), `CITATION.cff`, and the
  rewritten `README.md` and `code/README.md`.
- `scripts/verify_packaged_results.py` skips `.git/`, a virtual environment at the repository root, and Python
  bytecode caches, so it passes in a fresh `git clone` (at `v1.0.0` it reported them as forbidden files); every
  data-count and headline-metric check is unchanged.

## Integrity files

- `FILE_MANIFEST.tsv` — path and size of every file in git.
- `SHA256SUMS` — SHA-256 of every file in git (excluding itself); `shasum -a 256 -c SHA256SUMS`.
- `RESULT_FILE_LISTING.txt` — every result file under `results/`, `results_rebuttal/`, and `results_august/run_registry/`
  with size, SHA-256 and location (git or release tarball); the counts quoted in paper Appendix P come from this file.
- `RAW_OUTPUTS_MANIFEST.tsv` inside the release tarball, mirrored by the `RAW_OUTPUTS_IN_RELEASE.txt` notes.
- `TEST_LOG.txt` — fresh-clone CPU test run.

## Excluded by design

`.DS_Store`, `__pycache__`, `.pytest_cache`, `*.pyc`, virtual environments, Hugging Face caches and model weights,
tensor dumps, LaTeX build products, the review-time packaging checklist and planning notes, and the six
`DEBUG_ONLY`/`INVALID_DO_NOT_CITE` directories of the `results_rebuttal/` ledger.

## Provenance of the review-time archives

- `safekv_acl_supplement_software.zip` (review-time Software field) and `safekv_acl_supplement_data_results.zip`
  (review-time Data field) were complementary halves of the same tree; their content is contained in Layer 1.
- Both review-time archives passed CRC checks and their combined tree matched 541/541 recorded checksums at the
  time of the author response.
